# Visual research: technology B2B

For a new product or substantial redesign, research before setting layout and tokens. For a small component change, use 4–6 focused references; otherwise collect 12–20 references across at least three sources, including two of Pinterest, Dribbble, Behance, and 花瓣. Prefer work from the last 18 months, then compare it with a mature production design system.

Search with the product job, not “beautiful UI”: `AI operations console`, `cloud management dashboard`, `developer platform`, `enterprise analytics`, `权限管理 后台`, `数据平台 B端`. Add the current year when useful.

Create a short evidence ledger with URL, date if known, surface type, one transferable pattern, one risk, and relevance. Extract recurring decisions about hierarchy, density, navigation, typography, table treatment, chart annotation, and motion. Reject one-shot showcase effects that hide real workflows.

Synthesize; never reproduce a single composition, illustration, icon set, brand identity, or proprietary asset. Inspiration sources are not usability evidence. Validate the result against the actual user job, accessibility, existing product constraints, and rendered behavior.

Actively remove AI-default signals: interchangeable KPI-card rows, gratuitous blue-purple gradients, glowing blobs, glass panels without information purpose, excessive pills and rounded cards, fake charts, placeholder metrics, uniform spacing with no hierarchy, and generic marketing copy inside product UI. Keep a distinctive feature only when it follows from this product's domain.

If a source is blocked or requires login, use indexed result previews or substitute another source; do not bypass access controls. If browsing is unavailable or the user forbids it, use supplied references and existing project evidence, state the limitation, and do not claim the direction is trend-validated.
